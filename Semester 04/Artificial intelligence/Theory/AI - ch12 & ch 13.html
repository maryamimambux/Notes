Quantifying Uncertainty

How AI agents deal with partial observability, nondeterminism, and incomplete knowledge using the mathematical language of probability theory.

12.1 Acting Under Uncertainty

In the real world, agents almost never have complete knowledge of their environment. They face uncertainty due to three main sources:

Partial Observability: The agent's sensors don't reveal the full state of the world. A robot may not see around corners; a doctor can't directly inspect a patient's bloodstream.
Nondeterminism: Even knowing the full state, actions may have multiple possible outcomes. Flipping a switch might not always work.
Adversaries: Other agents in the environment may act in unpredictable or adversarial ways.

12.1.1 Why Logic Fails — The Summarizing Uncertainty Problem

Consider a dental diagnosis system. A logical agent might write:

Logical Rule (Broken) Toothache ⇒ Cavity // Wrong! Not all toothaches are from cavities Cavity ⇒ Toothache // Wrong! Not all cavities cause pain

Logic fails here for three fundamental reasons, which the book calls:

ReasonWhat It MeansExample
LazinessWriting truly exhaustive rules is impracticalToo many exceptions to toothache rules
Theoretical IgnoranceScience doesn't have a complete theoryNo complete dental theory exists
Practical IgnoranceEven with all rules, specific data may be missingPatient hasn't had all tests done

The solution: instead of true/false, assign a degree of belief — a number between 0 and 1 that represents how confident we are. This is what probability theory provides.

Key Insight: Probability statements are about knowledge states, not the world itself. "P(cavity | toothache) = 0.8" means: given that we currently know about a toothache and nothing else, 80% of such situations result in a cavity. The probability changes as we learn more.

12.1.2 Uncertainty and Rational Decisions

Knowing probabilities alone isn't enough — an agent also needs to know what outcomes are desirable. This gives us:

Decision Theory Decision Theory = Probability Theory + Utility Theory -- Probability: how likely is each outcome? -- Utility: how good/bad is each outcome? -- Rational agent: choose action with maximum EXPECTED utility
Example — The Airport Problem

Scenario

An automated taxi must get a passenger to the airport on time. Three plans:

PlanLeave TimeP(on time)Downside
A₉₀90 min before97%Reasonable
A₁₈₀180 min before99.5%Long airport wait
A₁₄₄₀24 hrs before≈100%Intolerable wait

A₉₀ is typically rational because it balances the probability of success against the cost (long wait, missed meals). The right choice depends on both probability AND utility of outcomes.

Principle of Maximum Expected Utility (MEU)

A rational agent chooses the action that yields the highest expected utility, averaged over all possible outcomes of the action — weighted by their probabilities.

12.2 Basic Probability Notation

Random Variables

A random variable is any aspect of the world about which we have uncertainty. In probability theory, they are written with capital letters and have a domain (the set of values they can take).

VariableDomain / Possible ValuesExample
Weather{sun, rain, fog, meteor}Is it raining?
Temperature{hot, cold}Is it hot outside?
Cavity{true, false}Does patient have cavity?
Die1{1, 2, 3, 4, 5, 6}Value of first die roll
Convention: Random variables → UPPERCASE (Cavity). Their specific values → lowercase (cavity, ¬cavity). Boolean variable "Cavity = true" is often just written as "cavity".

Probability Distributions

A probability distribution assigns a probability to each value in a variable's domain. These must satisfy two requirements:

Axioms of Probability 0 ≤ P(ω) ≤ 1 for every possible world ω Σ P(ω) = 1 all probabilities sum to 1
Example — Weather Distribution

The full distribution for Weather is written as a vector:

WP
sun0.6
rain0.1
fog0.3
meteor0.0

Check: 0.6 + 0.1 + 0.3 + 0.0 = 1.0 ✓

In bold-vector shorthand: P(Weather) = ⟨0.6, 0.1, 0.3, 0.0⟩

Prior vs. Posterior (Conditional) Probability

There are two types of probabilities:

TypeNotationMeaning
Prior / UnconditionalP(cavity) = 0.2Probability before observing any evidence
Posterior / ConditionalP(cavity | toothache) = 0.6Probability GIVEN we know something (evidence)

Joint Probability Distributions

A joint distribution specifies a probability for every possible combination of values of multiple variables. For n variables each with d values, the joint table has d^n entries.

Example — Joint Distribution Over T (Temperature) and W (Weather)
TWP(T,W)
hotsun0.4
hotrain0.1
coldsun0.2
coldrain0.3

Total: 0.4 + 0.1 + 0.2 + 0.3 = 1.0 ✓

This table answers ANY question about T and W — it is the "universal knowledge base" for this domain.

Reading probabilities from this table:

P(T=hot AND W=sun) → look up row: 0.4

P(T=hot) → add all rows with T=hot: 0.4 + 0.1 = 0.5

P(T=hot OR W=sun) → P(hot) + P(sun) − P(hot ∧ sun) = 0.5 + 0.6 − 0.4 = 0.7

Scaling Problem: A joint distribution over n Boolean variables needs 2ⁿ entries. With just 30 variables: 2³⁰ ≈ 1 billion entries. Completely impractical! This is why we need smarter representations like Bayes Nets (Chapter 13).

12.3 Inference Using Full Joint Distributions

Given a full joint distribution, we can answer any probabilistic query by summing up the relevant entries.

The Dental Example — Full Joint Distribution

Three Boolean variables: Toothache (T), Cavity (C), Catch (X) (dentist's probe catches in tooth).

toothache¬toothache
catch¬catchcatch¬catch
cavity0.1080.0120.0720.008
¬cavity0.0160.0640.1440.576

Total: all 8 values sum to 1.0 ✓

Query 1: P(cavity ∨ toothache) = ?

Identify all worlds where cavity OR toothache is true — that's all except the row ¬cavity,¬toothache:

P(cavity ∨ toothache) = 0.108 + 0.012 + 0.072 + 0.008 + 0.016 + 0.064 = 0.28

Query 2: P(cavity) = ?

Sum the entire cavity row (all combinations where cavity is true):

P(cavity) = 0.108 + 0.012 + 0.072 + 0.008 = 0.2

Query 3: P(cavity | toothache) = ?

Use conditional probability formula: P(a|b) = P(a ∧ b) / P(b)

P(toothache) = 0.108 + 0.012 + 0.016 + 0.064 = 0.2

P(cavity ∧ toothache) = 0.108 + 0.012 = 0.12

P(cavity | toothache) = 0.12 / 0.2 = 0.6

Marginalization and Normalization Trick

Marginalization (Summing Out)

Marginalization is the process of collapsing a joint distribution to a smaller one by summing out unwanted variables.

Marginalization Rule P(Y) = Σ_z P(Y, Z=z) -- Sum over all values of Z to eliminate it -- Also called "summing out" variable Z
Example — Marginalizing over Weather

Starting with joint P(T, W):

TWP
hotsun0.4
hotrain0.1
coldsun0.2
coldrain0.3

To get P(T) — marginalize over W (sum out W):

P(T=hot) = P(hot,sun) + P(hot,rain) = 0.4 + 0.1 = 0.5

P(T=cold) = P(cold,sun) + P(cold,rain) = 0.2 + 0.3 = 0.5

Result: P(T) = ⟨0.5, 0.5⟩

The Normalization Trick

When computing conditional probabilities from a joint distribution, we don't always need to know P(evidence) exactly. We can:

SELECT all rows from the joint table that match the observed evidence.
NORMALIZE those selected rows so they sum to 1 (divide each by their sum Z).
Normalization Procedure Step 1: Compute Z = sum of selected entries Step 2: Divide every entry by Z P(Y | evidence) = (1/Z) × P(Y, evidence) -- α = 1/Z is the normalization constant
Example — Normalization

Query: P(W | T=cold) from the joint P(T,W)

Step 1: SELECT rows where T=cold:

TWP (selected)
coldsun0.2
coldrain0.3

Step 2: NORMALIZE — Z = 0.2 + 0.3 = 0.5

P(W=sun | T=cold) = 0.2 / 0.5 = 0.4

P(W=rain | T=cold) = 0.3 / 0.5 = 0.6

Why does this work? The sum of selected rows IS P(evidence) = P(T=cold) = 0.5. So dividing by Z is the same as dividing by P(T=cold).

Inference by Enumeration — General Method

The general formula for answering any query P(X | e) from a joint distribution:

General Inference by Enumeration P(X | e) = α Σ_y P(X, e, y) Where: X = query variable e = evidence (observed values) y = hidden variables (not queried, not observed) α = normalization constant Steps: 1. Select entries consistent with evidence e 2. Sum out hidden variables Y to get P(X, e) 3. Normalize to get P(X | e)
Detailed Example — Inference by Enumeration

Joint distribution P(S, T, W) with 3 variables: Season (S), Temperature (T), Weather (W):

STWP
summerhotsun0.30
summerhotrain0.05
summercoldsun0.10
summercoldrain0.05
winterhotsun0.10
winterhotrain0.05
wintercoldsun0.15
wintercoldrain0.20

Query A: P(W) — no evidence

Sum over all values of S and T (both are hidden here):

P(W=sun) = 0.30 + 0.10 + 0.10 + 0.15 = 0.65

P(W=rain) = 0.05 + 0.05 + 0.05 + 0.20 = 0.35

Answer: P(W) = ⟨0.65, 0.35⟩

Query B: P(W | winter) — S is evidence, T is hidden

Step 1 — SELECT rows where S=winter:

STWP
winterhotsun0.10
winterhotrain0.05
wintercoldsun0.15
wintercoldrain0.20

Step 2 — SUM OUT T (hidden variable):

P(W=sun, winter) = 0.10 + 0.15 = 0.25

P(W=rain, winter) = 0.05 + 0.20 = 0.25

Step 3 — NORMALIZE: Z = 0.25 + 0.25 = 0.50

P(W=sun | winter) = 0.25/0.50 = 0.5

P(W=rain | winter) = 0.25/0.50 = 0.5

Query C: P(W | winter, hot) — S and T are both evidence

Step 1 — SELECT rows where S=winter AND T=hot:

P(W=sun, winter, hot) = 0.10

P(W=rain, winter, hot) = 0.05

Z = 0.10 + 0.05 = 0.15

P(W=sun | winter, hot) = 0.10/0.15 = 2/3 ≈ 0.667

P(W=rain | winter, hot) = 0.05/0.15 = 1/3 ≈ 0.333

Conditional Probability — Detailed

Definition of Conditional Probability P(a | b) = P(a ∧ b) / P(b) provided P(b) > 0 -- "Probability of a, GIVEN b has occurred" -- Restricts the sample space to worlds where b is true -- Among those worlds, what fraction also has a?
Disease Testing Example (Slides)

Given information:

Disease (D)Test Result (T)Joint Probability
+d (has disease)+t (positive test)0.045
+d-t (negative test)0.005
-d (no disease)+t0.095
-d-t0.855

Reading the table: P(+d) = 0.045 + 0.005 = 0.05 (5% have disease)

P(+t) = 0.045 + 0.095 = 0.14 (14% test positive)

Computing conditional probabilities:

P(+t | +d) = P(+t ∧ +d) / P(+d) = 0.045 / 0.05 = 0.9

Interpretation: Test detects disease 90% of the time (sensitivity = 90%)

P(+d | +t) = P(+t ∧ +d) / P(+t) = 0.045 / 0.14 ≈ 0.32

Interpretation: Only 32% of positive tests actually have the disease!

Counterintuitive result! Even though the test has 90% sensitivity, because the disease is rare (only 5% prior), most people who test positive are actually disease-free. This illustrates why prior probability matters enormously.

Product Rule and Chain Rule

Rearranging the conditional probability formula gives the Product Rule:

Product Rule P(a ∧ b) = P(a | b) × P(b) -- Also written: P(a, b) = P(a|b) P(b)
Product Rule Example — Computing Joint from Conditional

We know: P(Weather = sun) = 0.8 and P(Dress=wet | Weather) given below.

DWP(D|W)
wetsun0.1
drysun0.9
wetrain0.7
dryrain0.3

Using Product Rule P(D,W) = P(D|W) × P(W):

P(wet, sun) = 0.1 × 0.8 = 0.08

P(dry, sun) = 0.9 × 0.8 = 0.72

P(wet, rain) = 0.7 × 0.2 = 0.14

P(dry, rain) = 0.3 × 0.2 = 0.06

The Chain Rule extends the product rule to any number of variables:

Chain Rule (General) P(x₁, x₂, ..., xₙ) = P(xₙ|xₙ₋₁,...,x₁) × P(xₙ₋₁|xₙ₋₂,...,x₁) × ... × P(x₂|x₁) × P(x₁) = ∏ᵢ P(xᵢ | xᵢ₋₁, ..., x₁) -- Every joint distribution can ALWAYS be decomposed this way -- This identity is ALWAYS true for any variables

12.4 Independence

Two variables X and Y are independent (also: absolutely independent, marginally independent) when knowing the value of one tells you nothing about the other.

Independence — Three Equivalent Definitions P(X, Y) = P(X) × P(Y) (joint factors) P(X | Y) = P(X) (Y doesn't affect X) P(Y | X) = P(Y) (X doesn't affect Y)
Classic Independence Example — Dental Variables + Weather

The book shows that Weather (sun/rain/cloud/snow) is completely independent of dental problems (Toothache, Cavity, Catch). Common sense: the weather outside doesn't affect what's going on in your teeth!

This means we can FACTOR the joint distribution:

P(Toothache, Cavity, Catch, Weather) = P(Toothache, Cavity, Catch) × P(Weather) -- 8-entry table × 4-entry table = 12 numbers instead of 32!

Another independence example — Coin Flips

n independent coin flips: each flip P(Cᵢ) = ⟨0.5, 0.5⟩. All flips are independent, so:

P(C₁, C₂, ..., Cₙ) = P(C₁) × P(C₂) × ... × P(Cₙ) -- Full joint: 2ⁿ entries vs. Independent: n×2 entries -- n=30: 1 billion entries vs. 60 entries — HUGE savings!

12.5 Bayes' Rule and Its Use

Bayes' Rule is derived directly from the two forms of the product rule:

Derivation of Bayes' Rule P(a ∧ b) = P(a|b) × P(b) ...(1) P(a ∧ b) = P(b|a) × P(a) ...(2) Setting (1) = (2): P(a|b) × P(b) = P(b|a) × P(a) Divide both sides by P(a): P(b|a) = P(a|b) × P(b) / P(a) Or in general form: P(Y|X) = P(X|Y) × P(Y) / P(X)
Why is Bayes' Rule so powerful? It lets us compute the "reverse" conditional probability. In practice, we often know P(effect|cause) from domain knowledge, but we want P(cause|effect) — the diagnostic direction. Bayes' Rule flips the direction!

Components of Bayes' Rule

TermNameMeaning
P(H)PriorProbability of hypothesis H before seeing evidence
P(E)Likelihood of evidenceNormalizing constant — probability of evidence regardless of H
P(E|H)LikelihoodHow likely is evidence E if hypothesis H is true
P(H|E)PosteriorUpdated probability of H AFTER seeing evidence E
Example 1 — Meningitis Diagnosis (Book Example)

Given:

P(s | m) = 0.7 — stiff neck given meningitis: 70%

P(m) = 1/50,000 = 0.00002 — prior probability of meningitis

P(s) = 0.01 — prior probability of stiff neck (from any cause)

Find: P(m | s) — probability of meningitis given stiff neck

P(m | s) = P(s | m) × P(m) / P(s) = 0.7 × (1/50,000) / 0.01 = 0.7 × 0.00002 / 0.01 = 0.0014

Interpretation: Even though meningitis strongly causes stiff neck (70%), the chance of meningitis given a stiff neck is only 0.14%! This is because stiff necks are very common (1%) from many other causes, while meningitis is very rare.

Important note from slides: The posterior is small, but doctors should still check! Because missing meningitis has catastrophic consequences. The decision depends on both probability AND utility (cost of misdiagnosis).
Example 2 — Coins in a Bowl (Slides)

3 bowls, randomly selected. Bowl 1 has 2 red + 4 blue; Bowl 2 has 1 red + 5 blue; Bowl 3 has 5 red + 1 blue. A red coin is drawn.

Find: P(B1 | R) — probability it came from Bowl 1

P(B1|R) = P(R|B1) × P(B1) / P(R) P(B1) = 1/3 (equal chance of selecting any bowl) P(R|B1) = 2/6 = 1/3 P(R) = P(R|B1)P(B1) + P(R|B2)P(B2) + P(R|B3)P(B3) = (2/6)(1/3) + (1/6)(1/3) + (5/6)(1/3) = (2+1+5)/(18) = 8/18 = 4/9 P(B1|R) = (1/3)(1/3) / (4/9) = (1/9) / (4/9) = 1/4

Applying Bayes' Rule with Multiple Evidence

When there are multiple pieces of evidence (e.g., toothache AND catch in dental example), naive Bayes' rule requires computing P(toothache ∧ catch | Cavity) — which requires the full joint again. The key insight is to use conditional independence.

12.5.2 Conditional Independence

Conditional Independence is a much weaker (and more commonly available) form of independence. X and Y are conditionally independent given Z if, once we know Z, knowing X tells us nothing more about Y (and vice versa).

Conditional Independence Definition X ⊥ Y | Z (read: "X is independent of Y given Z") P(X, Y | Z) = P(X | Z) × P(Y | Z) Equivalent forms: P(X | Y, Z) = P(X | Z) P(Y | X, Z) = P(Y | Z)
Dental Example — Toothache ⊥ Catch | Cavity

Consider: Toothache depends on nerve state, Catch depends on whether probe catches in a hole. Both are caused by Cavity.

Claim: P(Toothache, Catch | Cavity) = P(Toothache | Cavity) × P(Catch | Cavity)

Why?

If we already KNOW the cavity is present, then the toothache tells us nothing extra about the probe catching — they are both just symptoms of the same known cause.

If we already KNOW there is NO cavity, then again, knowing about toothache doesn't change our belief about catch.

Power of this insight:

Without conditional independence: Need P(toothache ∧ catch | Cavity) — requires 2^2 = 4 numbers per value of Cavity With conditional independence: P(Toothache | Cavity) + P(Catch | Cavity) — requires 2+2 = 4 numbers total (vs. 8 numbers for the joint conditional)

Full decomposition with conditional independence:

P(Toothache, Catch, Cavity) = P(Toothache | Cavity) × P(Catch | Cavity) × P(Cavity) -- Original: 7 independent parameters -- With cond. independence: 5 independent parameters -- With n symptoms: O(n) instead of O(2^n)!
Slides Example — Toothache, Cavity, Catch, Weather

From the slides, the assumption is:

P(T, X, C, W) = P(T, X, C) × P(W)

where Catch = X-ray (abbreviated X in slide).

Weather is absolutely independent of dental variables.

Toothache and Catch are conditionally independent given Cavity.

Conditional independence, brought about by direct causal relationships, is the most fundamental and practically important form of probabilistic knowledge. It is what makes reasoning in complex domains tractable — and it is the foundation of Bayesian networks.

12.6 Naive Bayes Models

A Naive Bayes model assumes that all "effect" variables are conditionally independent given a single "cause" variable. The word "naive" reflects that this is an approximation — in reality, effects often do influence each other.

Naive Bayes Joint Distribution P(Cause, E₁, ..., Eₙ) = P(Cause) × ∏ᵢ P(Eᵢ | Cause) To classify (find most likely Cause given evidence E=e): MAP(H) = argmax P(H | e) = argmax P(e | H) × P(H) -- drop P(e), same for all H = argmax P(E₁|H) × P(E₂|H) × ... × P(Eₙ|H) × P(H)

Slides Example — Animal Classifier (Parrot/Dog/Fish)

Training data: 1500 records, 3 classes (500 each), 4 features: Swim, Wings, Green, Teeth

FeatureP(feat | Parrot)P(feat | Dog)P(feat | Fish)
Swim0.100.901.00
Wings1.000.000.00

Record 1: Evidence = {Swim=T, Green=T} — What animal?

P(Dog | Swim, Green) = P(Swim|Dog)×P(Green|Dog)×P(Dog)/P(evidence) = 0.9×0×0.333/P(e) = 0
P(Parrot | Swim, Green) = 0.1×0.80×0.333/P(e) = 0.0264/P(e)
P(Fish | Swim, Green) = 1.0×0.2×0.333/P(e) = 0.0666/P(e)
Since 0.0666 > 0.0264 > 0, classify as Fish!

Record 2: Evidence = {Swim=T, Green=T, Teeth=T}

P(Dog|...) = 0.9×0×1×0.333 = 0 (Green=0 wipes it out)

P(Parrot|...) = 0.1×0.8×0×0.333 = 0 (Teeth=0 wipes it out)

P(Fish|...) = 1.0×0.2×0.1×0.333 = 0.00666/P(e) → classify as Fish!

12.6.1 Text Classification with Naive Bayes

A very common application: given a text document, classify it into a category (news/sports/business/weather/entertainment). The "cause" is Category, the "effects" are the presence/absence of key words.

Estimate P(Category=c) as the fraction of training documents in that category.
Estimate P(HasWordᵢ | Category) as the fraction of documents in each category containing word i.
For new document: find which words are present, apply Naive Bayes, pick category with highest posterior.
Applications: Language detection, document retrieval, spam filtering, sentiment analysis. Naive Bayes works surprisingly well even when the independence assumption is violated! The ranking of categories is usually correct even if the actual probabilities are overconfident.

12.7 The Wumpus World Revisited

The book uses the wumpus world to demonstrate probabilistic reasoning with conditional independence.

Wumpus World Probability Problem

Setup: Agent has visited [1,1], [1,2], [2,1]. Found breezes in [1,2] and [2,1]. No pit in visited squares. Each unvisited square has P(pit) = 0.2 independently.

Query: P(pit in [1,3]) — how likely is [1,3] to contain a pit?

Key insight using conditional independence:

The breezes are conditionally independent of the "Other" unknown squares given the known, frontier, and query variables. This lets us avoid summing over all 4096 possible configurations of 12 unknown squares.

Result (from book calculation):

P(P₁₃ = pit | known, breeze) ≈ 0.31 P(P₂₂ = pit | known, breeze) ≈ 0.86

Conclusion: [2,2] is very dangerous (86% chance of pit)! A logical agent couldn't distinguish [1,3] from [2,2], but a probabilistic agent clearly should avoid [2,2] and prefer [1,3].

Probabilistic Reasoning — Bayesian Networks

A systematic, graphical approach to representing and computing with complex probabilistic relationships using directed acyclic graphs and conditional probability tables.

Chapter 12 showed that the full joint distribution can answer any question, but it is impractically large. Chapter 13 introduces Bayesian Networks — a way to represent the same information much more compactly by explicitly encoding conditional independence relationships.

13.1 Representing Knowledge in an Uncertain Domain

Bayesian Network (Bayes Net)

A directed acyclic graph (DAG) where each node is a random variable, each directed arrow represents a direct causal influence, and each node has a conditional probability table (CPT) quantifying the relationship with its parents.

Formal Specification of a Bayesian Network

Nodes: One per random variable — may be discrete or continuous.
Directed Links (Arrows): Arrow from X to Y means X is a parent of Y and has a direct influence on Y. The graph must have NO directed cycles (it is a DAG).
Conditional Probability Tables (CPTs): Each node Xᵢ has an associated probability distribution P(Xᵢ | Parents(Xᵢ)). This is a table with one row per combination of parent values.
A Bayes net = Topology (graph structure) + Local Conditional Probabilities (CPTs)

Simple Bayesian Network — Weather & Dental (Figure 13.1)

Figure 13.1 — Weather is independent. Toothache and Catch are conditionally independent given Cavity. No arrow between Toothache and Catch because no direct causal link exists.

Computing a Joint Probability from the Alarm Network

Query: P(burglary=T, earthquake=F, alarm=T, john=F, mary=T) = ?

P(b, ¬e, a, ¬j, m) = P(b) × P(¬e) × P(a|b,¬e) × P(¬j|a) × P(m|a) = 0.001 × 0.998 × 0.94 × 0.10 × 0.70 = ≈ 0.000028

This is the probability of this particular combination of events happening simultaneously. It's very small, but it's a specific scenario.

13.2 The Semantics of Bayesian Networks

Global Semantics — The Joint Distribution Formula

Bayes Net Global Semantics P(x₁, ..., xₙ) = ∏ᵢ P(xᵢ | parents(Xᵢ)) -- The full joint probability is the PRODUCT of all local CPT entries -- Each variable depends ONLY on its parents, not on all predecessors -- This is what makes Bayes nets compact!

Connection to Chain Rule

The chain rule says:

P(x₁,...,xₙ) = ∏ᵢ P(xᵢ | xᵢ₋₁, ..., x₁) (chain rule — always true)

The Bayes net says:

P(x₁,...,xₙ) = ∏ᵢ P(xᵢ | parents(Xᵢ)) (Bayes net — a special structure)

Comparing these two, the Bayes net is valid if and only if each node is conditionally independent of its non-parent predecessors given its parents. This is the key conditional independence assertion built into the graph structure.

Methodology for building a Bayes Net:
  1. List all variables. Order them with causes before effects.
  2. For each variable Xᵢ: find the minimal set of parents from earlier variables such that Xᵢ is conditionally independent of all other earlier variables given its parents.
  3. For each parent relationship, draw an arrow.
  4. Fill in the CPT for each variable given its parents.

Conditional Independence Properties in BNs

Non-Descendants Property

Each variable is conditionally independent of its non-descendants given its parents.

Markov Blanket Property

A variable is conditionally independent of ALL other nodes in the network given its Markov blanket = {parents, children, children's other parents}.

Markov Blanket Example — Burglary in Alarm Network

For node Burglary:

Parents: none (root node)

Children: Alarm

Children's other parents: Earthquake

Markov Blanket of Burglary = {Alarm, Earthquake}

This means: Burglary is independent of JohnCalls and MaryCalls, given Alarm and Earthquake.

13.2.2 Efficient Representation of Conditional Distributions

For large networks, explicitly writing out every CPT entry is expensive. Several canonical patterns allow compact representation:

1. Deterministic Nodes

A node whose value is completely determined by its parents (no uncertainty). Examples:

NorthAmerican = Canadian ∨ US ∨ Mexican (logical OR) BestPrice = min(Price1, Price2, ..., PriceN) (minimum function) WaterStored = Previous + Inflows − Outflows (arithmetic)

2. Context-Specific Independence (CSI)

A variable is independent of some parents given certain values of other parents.

CSI Example — Car Damage

P(Damage | Ruggedness, Accident):

If Accident=false, then Damage does NOT depend on Ruggedness (only minor vandalism, same for all cars).

If Accident=true, then Damage depends heavily on Ruggedness.

P(Damage | Ruggedness, Accident) = if (Accident = false) then d₁ else d₂(Ruggedness)

3. Noisy-OR Model

A generalization of logical OR for uncertain causal relationships. "Fever is caused by Cold, Flu, or Malaria — but each cause might be inhibited."

Noisy-OR for Fever (Figure 13.5)

Inhibition probabilities (q-values):

q_cold = P(¬fever | cold only) = 0.6 → i.e., Cold causes fever 40% of the time

q_flu = P(¬fever | flu only) = 0.2 → i.e., Flu causes fever 80% of the time

q_malaria = P(¬fever | malaria only) = 0.1 → i.e., Malaria causes fever 90% of the time

General Noisy-OR Rule:

P(¬child | parents) = ∏_{j: Xⱼ=true} qⱼ -- Fever absent iff ALL active causes are inhibited -- Inhibitions are INDEPENDENT of each other

Example calculation — P(¬fever | cold=T, flu=T, malaria=F):

P(¬fever | cold, flu, ¬malaria) = q_cold × q_flu = 0.6 × 0.2 = 0.12

P(fever | cold, flu, ¬malaria) = 1 − 0.12 = 0.88

13.3 Exact Inference in Bayesian Networks

Given a Bayes net, how do we compute P(X | e) — the posterior probability of a query variable given evidence?

13.3.1 Inference by Enumeration

The basic approach: sum over the full joint distribution (restricted to values consistent with evidence), then normalize.

Enumeration Formula for Bayes Net Inference P(X | e) = α Σ_y P(X, e, y) = α Σ_y ∏ᵢ P(xᵢ | parents(Xᵢ)) -- y = hidden variables (not query, not evidence) -- Complexity: O(n × 2ⁿ) naive, O(2ⁿ) with nested structure
Alarm Network — Query: P(Burglary | JohnCalls=T, MaryCalls=T)

Hidden variables: Earthquake (E), Alarm (A)

P(B | j, m) = α Σ_e Σ_a P(B, j, m, e, a) = α Σ_e Σ_a P(B) P(e) P(a|B,e) P(j|a) P(m|a) For B=true: P(b|j,m) = α Σ_e Σ_e P(b) P(e) P(a|b,e) P(j|a) P(m|a)

Using nested sums and looking up from CPT tables:

P(b|j,m) = α × 0.00059224

P(¬b|j,m) = α × 0.0014919

Normalize: α = 1/(0.00059224 + 0.0014919)

P(B|j,m) ≈ ⟨0.284, 0.716⟩ — about 28% chance of burglary given both called!

13.3.2 Variable Elimination Algorithm

Enumeration recomputes the same subexpressions many times. Variable Elimination (VE) solves this by computing each sub-result once and caching it.

The key idea: move summations INWARD as far as possible. Instead of computing the full joint and then summing, compute partial products and sum out variables one at a time. This can dramatically reduce the computation.

Operations in Variable Elimination

1. Factors: A factor is a table indexed by some variables, containing non-negative numbers (not necessarily summing to 1). Initially, each factor is a CPT entry.

2. Pointwise Product: Multiply two factors by combining their variable lists and computing entry-by-entry products for all matching combinations.

Pointwise Product Example (Figure 13.12)

f(X,Y) × g(Y,Z) = h(X,Y,Z)

3. Summing Out (Marginalization): Sum a factor over one of its variables to produce a smaller factor.

Summing Out Example

To sum out X from h(X,Y,Z):

h₂(Y,Z) = Σ_x h(X,Y,Z) = h(x=T,Y,Z) + h(x=F,Y,Z) h₂(T,T) = 0.06 + 0.18 = 0.24 h₂(T,F) = 0.24 + 0.72 = 0.96 h₂(F,T) = 0.42 + 0.06 = 0.48 h₂(F,F) = 0.28 + 0.04 = 0.32

General Variable Elimination Algorithm

Initialize: Create one factor per node from its CPT. Apply evidence: restrict any evidence variable to its observed value.
Eliminate hidden variables one by one: For each hidden variable H, collect all factors containing H, compute their pointwise product, then sum out H.
Finish: Multiply remaining factors (over query variable and evidence) and normalize.
VE on Alarm Network — P(B | j, m)

Factors: f₁(B)=P(B), f₂(E)=P(E), f₃(A,B,E)=P(A|B,E), f₄(A)=P(j|A), f₅(A)=P(m|A)

Evidence: j=true (fixes f₄), m=true (fixes f₅)

Step 1: Eliminate A (sum out A)

f₆(B,E) = Σ_a f₃(a,B,E) × f₄(a) × f₅(a) = f₃(T,B,E)×f₄(T)×f₅(T) + f₃(F,B,E)×f₄(F)×f₅(F) -- Result: a 2×2 table over B and E

Step 2: Eliminate E (sum out E)

f₇(B) = Σ_e f₂(e) × f₆(B,e) = f₂(T)×f₆(B,T) + f₂(F)×f₆(B,F) -- Result: a 2-element vector over B

Step 3: Multiply remaining factors and normalize

P(B | j, m) = Normalize(f₁(B) × f₇(B)) ≈ Normalize(⟨0.00059224, 0.0014919⟩) ≈ ⟨0.284, 0.716⟩

Variable Ordering and Complexity

The order you eliminate variables MATTERS! Different orderings create different intermediate factors of different sizes. The time and space complexity is dominated by the SIZE of the largest factor created. Finding optimal ordering is NP-hard, but good heuristics exist (greedy: eliminate the variable that creates the smallest next factor).
Ordering Effect — Naive Bayes Network

Network: Z → {X₁,...,Xₙ} → {Y₁,...,Yₙ} (common cause with multiple effects and children)

Order 1: Eliminate Z, X₁, ..., Xₙ₋₁ first

Creates a factor of size 2^(n+1) — exponential!

Order 2: Eliminate Xᵢ then Yᵢ together for each i

Each factor stays size 2² — polynomial!

Order 2 insight: P(X₁|Z) × P(Y₁|X₁) = P(X₁,Y₁,Z) → sum out X₁ → P(Y₁,Z) Each pair creates factor of size only 4!

NP-hardness proof: Bayesian network inference can encode 3-SAT. If P(Z=true) > 0, the formula is satisfiable. Since 3-SAT is NP-hard, BN inference is NP-hard. In fact it's #P-hard — even counting the number of satisfying assignments is hard.

13.3.4 Clustering (Join Tree) Algorithms

For computing posterior probabilities of ALL variables, variable elimination would require O(n) queries at O(n) each = O(n²). Clustering algorithms combine individual nodes into cluster nodes forming a polytree, then do message-passing, achieving O(n) total time.

Clustering Example — Sprinkler Network (Figure 13.15)

The network Cloudy → {Sprinkler, Rain} → WetGrass is multiply connected (Rain and Sprinkler both affect WetGrass, and both are affected by Cloudy).

Solution: merge Sprinkler and Rain into one "meganode" Sprinkler+Rain with 4 values: {TT, TF, FT, FF}. Now the network is a polytree and message-passing is efficient.

13.4 Approximate Inference — Monte Carlo Methods

When exact inference is intractable, we use randomized sampling (Monte Carlo) algorithms to get approximate answers. The idea: generate random samples from the distribution and count outcomes to estimate probabilities.

13.4.1 Direct Sampling — Prior Sampling

The simplest approach: generate complete events by sampling each variable in topological order, conditioned on the values already sampled for its parents.

Prior Sampling — Sprinkler Network

Variables in order: Cloudy, Sprinkler, Rain, WetGrass

Sample from P(Cloudy) = ⟨0.5, 0.5⟩ → get true
Sample from P(Sprinkler | Cloudy=true) = ⟨0.1, 0.9⟩ → get false
Sample from P(Rain | Cloudy=true) = ⟨0.8, 0.2⟩ → get true
Sample from P(WetGrass | Sprinkler=F, Rain=T) = ⟨0.9, 0.1⟩ → get true

Result: event = [true, false, true, true] with probability 0.5×0.9×0.8×0.9 = 0.324

This process generates samples exactly according to the prior distribution. Generate many samples and count to estimate any probability.

Rejection Sampling

To answer conditional queries P(X | e): generate prior samples, reject (discard) any sample that doesn't match the evidence, count the rest.

Rejection Sampling for j = 1 to N: x ← PRIOR-SAMPLE(bn) if x matches evidence e: count x[query] P(X | e) ≈ (count of X values among kept samples) / (total kept)
Problem: If evidence is rare, most samples are rejected! The fraction accepted = P(evidence). For P(e) = 0.001, we reject 99.9% of samples — extremely slow convergence. Rejection sampling is essentially useless when evidence has low probability.

Likelihood Weighting (Importance Sampling)

Instead of rejecting samples, weight them by how well they match the evidence. This uses all generated samples.

Fix evidence variables to their observed values (don't sample them).
Sample non-evidence variables in topological order, conditioned on parents (which may include fixed evidence variables).
Compute weight = product of P(evidence variable = observed value | its parents) for all evidence variables.
Accumulate weighted counts for the query variable, then normalize.
Likelihood Weighting Formula Weight w = ∏ᵢ P(eᵢ | parents(Eᵢ)) -- Product over evidence variables Eᵢ of their CPT entries -- Each sample x gets weight w(x) P̂(X=x | e) = Σ_{samples with X=x} w(sample) / Σ_{all samples} w(sample)
Likelihood Weighting Example — Sprinkler Network

Query: P(Rain | Cloudy=true, WetGrass=true)

Order: Cloudy (evidence), Sprinkler, Rain, WetGrass (evidence)

Cloudy is evidence=true. w ← 1.0 × P(Cloudy=T) = 0.5
Sample Sprinkler from P(Sprinkler|Cloudy=T)=⟨0.1,0.9⟩ → get false
Sample Rain from P(Rain|Cloudy=T)=⟨0.8,0.2⟩ → get true
WetGrass is evidence=true. w ← 0.5 × P(WetGrass=T|Sprinkler=F,Rain=T) = 0.5 × 0.9 = 0.45

Sample: [true, false, true, true], weight = 0.45. Count under Rain=true.

Advantage over rejection sampling: Uses ALL samples, not just those matching evidence. Works better when evidence is downstream (early in topological order) so that samples are guided toward relevant regions.

Limitation: Pays less attention to downstream evidence. Samples generated before the evidence node don't "know" what the evidence will be, so many will have very low weights. This is like simulating randomly and then correcting after the fact.

13.4.2 Markov Chain Monte Carlo (MCMC) — Gibbs Sampling

MCMC algorithms don't generate each sample from scratch. Instead, they maintain a current state and make small random changes to it, generating a sequence of correlated samples.

Gibbs Sampling Algorithm

Start with a random assignment (evidence variables fixed). Repeatedly pick a non-evidence variable and resample it from its conditional distribution given the current values of its Markov blanket. Count each state visited as a sample.

Gibbs Sampling — Markov Blanket Sampling P(xᵢ | mb(Xᵢ)) = α P(xᵢ | parents(Xᵢ)) × ∏_{Yⱼ ∈ Children(Xᵢ)} P(yⱼ | parents(Yⱼ)) -- Only need to look at local neighborhood! -- Work per step is independent of network size
Gibbs Sampling — Sprinkler Network

Query: P(Rain | Sprinkler=true, WetGrass=true)

Non-evidence variables: Cloudy, Rain. Initialize randomly: [true, true, false, true] (bold = evidence fixed)

Iteration 1: Choose Cloudy. Sample from P(Cloudy | Sprinkler=T, Rain=F) using Markov blanket formula. Suppose result: Cloudy=false. State: [false, T, F, T]
Iteration 2: Choose Rain. Sample from P(Rain | Cloudy=F, Sprinkler=T, WetGrass=T). Suppose result: Rain=true. State: [F, T, T, T]
Continue... Each state is a sample. Count states where Rain=true.

Computing P(Cloudy | Sprinkler=T, Rain=F):

P(c | s=T, r=F) = α P(c)×P(s=T|c)×P(r=F|c) = α × 0.5 × 0.1 × 0.2 = α × 0.01 P(¬c | s=T, r=F) = α P(¬c)×P(s=T|¬c)×P(r=F|¬c) = α × 0.5 × 0.5 × 0.8 = α × 0.20 Normalized: P(c|s,¬r) ≈ 0.048, P(¬c|s,¬r) ≈ 0.952

Why Gibbs Sampling Works — Theoretical Justification

The sequence of states generated by Gibbs sampling forms a Markov chain. Key concepts:

ConceptMeaning
Transition Kernel k(x→x')Probability of moving from state x to state x'
Stationary Distribution πDistribution that doesn't change under transitions: π(x') = Σ_x π(x)k(x→x')
Detailed Balanceπ(x)k(x→x') = π(x')k(x'→x) — implies stationarity
ErgodicityEvery state is reachable from every other state, no periodic cycles
Key theorem: Gibbs sampling satisfies detailed balance with π(x) = P(x|e) — the true posterior. Therefore, if the chain is ergodic (no zero-probability CPT entries to block transitions), samples eventually converge to the correct posterior distribution.
When Gibbs sampling fails: If CPTs have 0/1 probabilities (deterministic relationships), ergodicity breaks. For example, if Rain is always the same as Cloudy, the chain gets stuck and never explores the other possibility.

Metropolis-Hastings (MH) Sampling

A more general MCMC algorithm that overcomes limitations of Gibbs sampling.

Propose a new state x' from a proposal distribution q(x'|x).
Accept or reject with probability: a(x'|x) = min(1, π(x')q(x|x') / π(x)q(x'|x))
If rejected, stay at current state x.
Remarkable property: MH converges to the correct stationary distribution for ANY ergodic proposal distribution — guaranteed by the detailed balance condition. Freedom to design clever proposal distributions allows escaping regions where Gibbs gets stuck.

Independence in Bayes Nets — D-Separation

Given a Bayes net, we can determine whether any two variables are conditionally independent by analyzing the graph structure.

Three Canonical Patterns (Triples)

PatternStructureIndependent (given nothing)?Independent given middle node?
Causal ChainX → Y → ZNo (X can influence Z through Y)Yes! Knowing Y blocks the path

Common Effect (V-structure)X → Y ← ZYes! X and Z are independentNo! Knowing Y activates the path
Causal Chain — Low Pressure → Rain → Traffic

Without knowing Rain: Low pressure and Traffic are correlated. Low pressure → rain → traffic, so they're not independent.

Given Rain: If I know it's raining, then whether there was low pressure tells me nothing extra about traffic. Rain "screens off" the upstream cause from the downstream effect.

From slides: "If I know that it is raining, and there is traffic, I don't need to know whether there is low pressure to understand the traffic."

Common Cause — Project Due → {Forums Busy, Lab Full}

Without knowing if project is due: If forums are busy, that suggests a project might be due, which increases probability lab is full. They're correlated.

Given project is due: Once I know the project deadline is the cause, whether forums are busy or lab is full no longer affects my belief about the other. The common cause "explains" their correlation.

Common Effect (V-structure) — Rain, Ballgame → Traffic

Without knowing Traffic: Rain and Ballgame are independent. They're unrelated — knowing one tells nothing about the other.

Given Traffic = true: Now they become dependent! "Explaining away" — if I know there's traffic and I also know it's raining (explains the traffic), the probability of a ballgame goes down. They compete as explanations.

This is backwards from causal chains and common causes — observing the effect activates dependence between causes!

D-Separation Algorithm

D-Separation (Directional Separation)

Variables X and Y are d-separated by a set Z if all undirected paths between X and Y are "blocked" by Z. If d-separated, then X ⊥ Y | Z (they are conditionally independent given Z).

Active vs. Inactive Triples

A path is active if every triple on the path is active. A path is blocked if any triple is inactive. All inactive paths → d-separated → conditionally independent.

Triple TypeActive (path continues) when...Blocked (path stops) when...
Causal Chain A→B→CB is NOT observedB IS observed (evidence shades B)
Common Cause A←B→CB is NOT observedB IS observed
V-structure A→B←CB OR any descendant of B IS observedB and all descendants are NOT observed
D-Separation Example — Traffic Network

Network: Low Pressure → Rain; Rain → Traffic; Ballgame → Traffic; Traffic → Traffic Report

Are Rain and Ballgame d-separated given Traffic Report?

Path: Rain → Traffic ← Ballgame (v-structure at Traffic)

Traffic Report is a descendant of Traffic. So observing Traffic Report "activates" the v-structure at Traffic.

→ Path is ACTIVE → Rain and Ballgame are NOT d-separated given Traffic Report.

→ They are dependent given Traffic Report (makes sense: knowing traffic situation and traffic report gives us info about both rain and ballgame).

Complete D-Separation Procedure

Consider ALL undirected paths between X and Y (ignoring arrow directions).
For each path, check every triple. Is the triple active or inactive given evidence Z?
A path is active iff ALL its triples are active. A path is blocked iff ANY triple is inactive.
If ALL paths from X to Y are blocked → X and Y are d-separated → X ⊥ Y | Z.
If ANY path is active → independence is NOT guaranteed.

13.5 Causal Networks

A regular Bayesian network encodes probabilistic dependencies but doesn't distinguish correlation from causation. Causal Networks (also called Structural Causal Models) go further by encoding actual cause-effect relationships.

Observational vs. Interventional Distributions

Key distinction: In standard probability, P(Y | X=x) means "given that we observe X=x, what is Y?" In causal networks, P(Y | do(X=x)) means "if we forcibly SET X=x (intervene), what is Y?" These can be very different!
Sprinkler Example — do vs. observe

In the Sprinkler network: Cloudy → Sprinkler; Cloudy → Rain; Sprinkler,Rain → WetGrass

Observing Sprinkler=true:

P(Cloudy | Sprinkler=T) — seeing sprinkler is on suggests it's probably cloudy (since cloudy weather makes people less likely to turn on sprinkler, so observing sprinkler on when cloudy is LESS common). Actually from the CPT, when Cloudy sprinkler probability is lower, so sprinkler=T is evidence against Cloudy.

Intervening do(Sprinkler=true):

P(Cloudy | do(Sprinkler=T)) = P(Cloudy) — forcing sprinkler on from outside the system tells us NOTHING about the weather! We've broken the causal link from Cloudy to Sprinkler.

The Do-Operator and Mutilated Networks

Notation: do(X=x) means "force variable X to take value x through external intervention".
Effect on network: Remove all arrows INTO the intervened variable. It no longer depends on its normal parents — we've overridden the natural mechanism.
Compute: Run inference on this "mutilated" network.
Do-Operator Formula (Adjustment Formula) P(Xᵢ | do(Xⱼ=x)) = Σ_{parents(Xⱼ)} P(xᵢ | xⱼ, parents(Xⱼ)) × P(parents(Xⱼ)) -- Weight the effect by the prior on Xⱼ's parents -- "What would happen across all possible contexts?"

Back-Door Criterion

To determine the causal effect of X on Y, we need to "close the back door" — block all non-causal paths (confounding paths). If we can find a set Z that closes the back door (d-separates X from its parents given X and Z), then:

Back-Door Adjustment Formula P(Y | do(X=x)) = Σ_z P(Y | X=x, Z=z) × P(Z=z) -- Z must block all back-door paths (non-causal confounding paths) -- Key to establishing causation from observational data!

The slides define "factors" as the working objects in VE:

Why Variable Elimination is Better — The Key Algebraic Trick

The slides show this is fundamentally about exploiting distributive law:

Algebraic Insight Naïve: uwy + uwz + uxy + uxz + vwy + vwz + vxy + vxz Factored: (u+v)(w+x)(y+z) -- Same result, massively fewer multiplications! -- This is what VE exploits: don't multiply everything together first -- Factor out terms that don't depend on the variable being summed

Worst-Case Complexity and Polytrees (Slides)

NP-hardness via SAT reduction (from slides): If we can compute P(Z = 0 or not), we can answer 3-SAT. Each Boolean clause becomes a CPT entry. Each propositional variable becomes a root node with P=0.5. The conjunction S is true iff ALL clauses are satisfied. So P(S=true) = (number of satisfying assignments) / 2^n. If P(S=true) = 0, unsatisfiable; else satisfiable.
Polytree

A directed graph where there is at most ONE undirected path between any two nodes. For polytrees, exact inference is always efficient (linear time). You can always find a good variable ordering.

Bayes Net Summary — From Slides

The spectrum from strict independence (most compact, least expressive) to full joint (most expressive, most expensive). Bayes Nets allow flexible tradeoff.

Final Key Insight: Bayesian networks play the same role in probabilistic reasoning that propositional logic plays in deterministic reasoning. They are a systematic, principled, and compact way to represent and reason about uncertain knowledge. The choice between exact and approximate inference depends on the size and structure of the network and the required precision of the answer.
